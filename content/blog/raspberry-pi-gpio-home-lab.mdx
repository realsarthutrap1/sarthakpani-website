## The boundary is the point

On a screen, a program can pretend the world is tidy. GPIO pins remove that
option. A signal is high or low. A wire is connected or it is not. Timing,
power, noise, and the tiny mistakes between a diagram and a real room all show
up in the behavior.

This home-lab project is about learning that boundary directly: reading input,
driving output, and using a Raspberry Pi as more than a small Linux computer.

## What I want to learn

- how to design safe GPIO experiments;
- how software timing changes physical behavior;
- how to document a setup so I can rebuild it later; and
- how a small computer becomes a useful instrument at home.

The goal is not to make a dramatic robot. It is to make the invisible parts of
software visible enough to debug.
